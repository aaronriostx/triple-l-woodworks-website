# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static marketing website for Triple L Woodworks, a custom cabinetry business. Plain HTML/CSS/JS — no build step, no package manager, no framework, no tests. Four main pages: `index.html` (projects/home), `about.html`, `faq.html`, `contact.html`, plus one detail page per featured project (`project-01.html`, `project-02.html`, `project-03.html`) and a workshop page (`shop.html`, "Workshop" in the nav and also linked from the "Inside the shop" section of the home page), all sharing one stylesheet (`styles.css`) and the theme script (`theme.js`). The project detail pages and `shop.html` also load `lightbox.js` (with `defer`).

## Commands

There is no build, lint, or test tooling. To preview changes, open the HTML files directly in a browser (`open index.html` on macOS) or serve the directory with any static file server. There is nothing to compile or install.

To check a layout change without a human looking, take a headless screenshot at desktop (1280) and phone (400) widths, e.g. `/Applications/Firefox.app/Contents/MacOS/firefox --headless --no-remote --profile <tmp-profile> --window-size=1280,2000 --screenshot out.png file://$PWD/index.html`. Two things make a naive screenshot misleading: entrance animations are caught mid-fade (set `ui.prefersReducedMotion` to `1` in the temp profile's `user.js`), and `loading="lazy"` images below the fold show as alt text (screenshot a temporary copy with the attribute stripped).

## Architecture

**Shared-markup pattern, not templating.** Each HTML page repeats the same header/nav/footer markup verbatim (including the logo `<img>` tag and theme-toggle button). There is no includes system — when changing the header, nav, footer, or site-wide markup, edit every HTML file (the four main pages, each `project-NN.html`, and `shop.html`) identically rather than editing one and expecting it to propagate. The only per-page differences are which nav link carries `aria-current` (`"page"` on the page itself; project pages mark Projects with `aria-current="true"`) and the second footer link. The nav ends with an Instagram icon link (`.nav-social`, an inline SVG using `currentColor`); the Instagram URL also appears in every footer (`.footer-links`) and in `contact.html`.

**Single stylesheet, append-only sections.** `styles.css` is one file organized as a long minified base rule block followed by clearly separated, commented, human-readable sections appended over time (about-page layout, motion/animation, logo handling, theme colors, FAQ disclosures, about photo, project cards and detail pages, portrait project photos, shop teaser, footer links, nav Instagram icon). When adding styles, follow this pattern: append a new commented section rather than interleaving rules into the minified base block.

**Theming is CSS-variable + data-attribute driven.** Colors are defined as custom properties on `:root`, with a dark variant under `:root[data-theme="dark"]` and a `prefers-color-scheme` media query fallback for when JS is disabled. `theme.js` is a small IIFE that runs before paint: it reads `localStorage['triple-l-theme']`, sets `root.dataset.theme`, and wires the toggle button's click handler. It intentionally fails open if `localStorage` is blocked (falls back to the OS preference) and syncs theme choice across tabs/pages via the `storage` event. Any new color used in CSS must be added as a variable in both the light (`:root`) and dark (`:root[data-theme="dark"]`) blocks, plus the `@media (prefers-color-scheme: dark)` no-JS fallback, to stay consistent.

**Logo is one PNG, styled two ways.** `assets/triple-l-logo.png` is the only logo file. In light mode it's blended onto the page background via `mix-blend-mode: multiply`; in dark mode it's inverted via `filter: invert(1)` plus `mix-blend-mode: screen`. There is no separate dark-mode logo file — don't add one without a reason; the filter approach is deliberate per the README.

**Motion is CSS-only and respects `prefers-reduced-motion`.** Page-to-page fades use the `@view-transition` CSS API (supported browsers only, degrades to normal navigation elsewhere). Entrance animations, hover lifts, and button press effects are all plain CSS keyframes/transitions gated behind `@media (hover: hover) and (pointer: fine)` and disabled wholesale under `@media (prefers-reduced-motion: reduce)`. No JS animation libraries are used or should be introduced.

**Much of the content is still placeholder.** Real so far: the about photo, the main photos and galleries for all three projects, and the contact email, Instagram link, and service areas. Still placeholder: the about story, all project titles/descriptions/stories, and the workshop text and photos. Placeholders are marked with placeholder text and HTML comments showing the exact markup to swap in (e.g. `<img class="project-photo" src="assets/...">`, `<a href="mailto:...">`). When filling in real content, follow the commented example markup already in place rather than inventing new structure, and add new project photos as `<article class="project">` copies per the pattern in `index.html`. Each project card links to a `project-NN.html` detail page; adding a project means copying both the card and a detail page.

**Photos are web-sized JPEGs with explicit dimensions.** Photos live in `assets/` (`assets/project-NN/` per project, `assets/shop/` for the workshop). The owner drops in phone originals (roughly 4000 px wide, or large PNGs); make a ~1600 px wide JPEG copy with `sips` and reference that, don't overwrite the original, and tell the owner the original is unused so it stays out of the commit. Check new photos for GPS metadata before they are published, since they are taken in clients' homes. Every `<img>` gets real `width`/`height` attributes and descriptive `alt` text; `.project-photo` sets `height: auto` so the CSS `aspect-ratio` crop wins over the `height` attribute. Videos are deliberately not stored in the repo — the owner chose YouTube embeds, not yet built.

**Photos on detail pages enlarge on click.** `lightbox.js` finds every `img.project-photo` inside `.project-page`, wraps each in a `.photo-zoom` button with a corner expand icon, and opens it in a native `<dialog class="lightbox">` (arrows/swipe step through the page's photos, Escape or a click outside closes). New photos added with the usual markup are picked up automatically; no extra markup is needed. Without JS the photos simply stay in place.

**Page layouts reuse a small set of classes.** Project detail pages and `shop.html` share one structure: `.contact-page.project-page` wrapper, a main photo, `.contact-layout.project-layout` holding `.about-story` plus an `.inquiry-guide` facts panel, then a `.project-gallery` grid. The main photo has two variants: a wide `.project-lead` (16:9, full width, above the layout — `shop.html`) or a `.project-portrait` (3:4) placed inside the layout beside a `.project-body` wrapper (`project-01.html`, `project-02.html`, `project-03.html`). Pick the variant that fits the photo's orientation instead of cropping a portrait photo into the wide slot. Home page cards crop to 4:5 (4:3 on phones).

## Deployment

Designed for GitHub Pages, deployed from the `main` branch root (see `README.md` for the full publish checklist). HTML files must stay at the repo top level, not nested in a subfolder, for relative links and GitHub Pages to work.
